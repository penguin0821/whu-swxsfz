# 开发使用手册

面向没有参与过本项目、需要接手继续维护或二次开发的人。读完这份文档，你应该能独立完成：改内容 → 构建 → 本地验收 → 部署上线。

---

## 1. 产物形态与设计取舍

整站是一个**单文件静态网页** `index.html`，约 1.35 MB。它有三个硬约束，理解这三点就理解了这个项目的所有"奇怪"设计：

1. **零外部依赖**。图片、字体、脚本全部 base64 内联在一个 HTML 里，不引任何 CDN、不外链任何 css/js/字体文件。好处是丢到任何静态托管甚至本地双击都能跑，没有跨域、没有资源 404、没有构建产物路径问题。代价是文件大、且资源改动要走注入流程。
2. **无框架、无打包器**。原生 JS + CSS + Canvas 2D。没有 npm、没有 webpack/vite、没有 node_modules。唯一的"构建工具"是一个 Python 脚本 `reinject6.py`，它做的事只是字符串替换（把 base64 塞进模板占位符）+ 字体子集化。
3. **模板与产物分离**。真源是 `demo6_template.html`，产物是 `index.html`。任何时候都只改模板，改完重新构建。

这三点决定了：内容更新门槛低（改文本即可），但资源更新（换图、加生僻字）需要走构建脚本。

## 2. 技术栈

| 层 | 用什么 | 说明 |
|----|--------|------|
| 结构 | 原生 HTML5 | 五个 section：首屏 / 研究方向 / 成员 / 成果 / 新闻。 |
| 样式 | 原生 CSS + CSS 变量 | 双色底：深墨绿 `#16211A`（舞台）+ 暖纸 `#F3EDE2`（内容区）。主题色都走 `:root` 变量。 |
| 交互 | 原生 JavaScript（ES6） | 无框架。双语切换、搜索浮层、成员弹窗、标签筛选都是手写。 |
| 首屏地球 | Canvas 2D 逐帧绘制 | 用一张 120×60 的陆地 bitmask 做镂空球体，不贴海，靠大气光晕 + 屏幕空间主光塑形。 |
| 字体 | 思源宋体子集 woff2，base64 内联 | 两个字重（Regular / SemiBold），只含站内实际用到的字。 |
| 图片 | webp/png，base64 内联 | logo、浮岛、枝干、导师照片。 |
| 构建 | Python 3 + fontTools | `reinject6.py`。fontTools 仅在重新子集化字体时才需要。 |
| 部署 | GitHub Pages（静态托管） | 仓库根目录的 `index.html` 即线上页面。 |

## 4. 构建流程：`reinject6.py` 做了什么

运行 `python3 reinject6.py`，它按顺序做五件事：

1. **提取汉字**：扫描 `demo6_template.html`，取出所有 CJK 字符（含中日韩统一表意文字、全角标点等三个 Unicode 区段）。
2. **并集到 charset_live.txt**：把新出现的字并入 `fonts/charset_live.txt`。这个清单**只增不减**（单调），保证历史上用过的字永远留在子集里。
3. **按需重新子集化字体**：把 charset_live 与当前 woff2 的 cmap 对比，若有缺字，用 `fontTools.subset` 从 OTF 重新切两个字重的 woff2，再重新 base64 写回 `fonts/v5_font_*.b64.txt`。
4. **注入资源**：把 logo、浮岛、枝干、陆地掩膜、两字重字体、导师照片的 base64 替换进模板的 `{{LOGO_B64}}` / `{{ISLAND_B64}}` / `{{BRANCH_B64}}` / `{{LAND_B64}}` / `{{FONT_REG_B64}}` / `{{FONT_SB_B64}}` / `{{PHOTO_B64}}` 占位符。若还有 `{{` 残留，直接 `assert` 失败。
5. **字形守卫**：构建结束后，检查产物 `index.html` 里出现的每个汉字是否都在 woff2 子集里；缺字则**硬断言报错**，绝不静默发布一个"某些字回退成系统字体、基线错位"的页面。

输出：根目录 `index.html`。

### OTF 源文件不在时怎么办

完整 OTF 每个约 11.6 MB，为保持仓库轻量**不入库**。因此脚本对"OTF 缺失"做了优雅降级：

- **OTF 不在**（刚 clone 的默认状态）：跳过重新子集化，直接复用已提交的 woff2 子集构建。若模板里出现了子集没有的**新汉字**，只打印 WARNING（列出缺哪些字），仍会构建成功——这些字会临时回退系统字体。
- **OTF 在**（按 `fonts/README.md` 下载放入后）：恢复完整能力，自动重切子集，且第 5 步的字形守卫变回**硬断言**。

实践含义：**纯改文案、复用现有汉字**，clone 后可直接构建，无需 OTF。**一旦引入新汉字**（新成员名字、新论文标题里的生僻字），必须放入 OTF 重新构建，否则那个字会基线错位。

搜索图标 `⌕` 等 UI 符号是**故意**走系统回退的（思源宋体本身不提供），脚本内置了 `ICON_FALLBACK` 豁免集，不会误报。

## 5. 字体子集化管线

为什么不用现成的完整字体：思源宋体完整字重每个十几 MB，内联进单文件会让页面爆炸。所以只切"站内真正用到的那几百个字"。

管线（由 `reinject6.py` 自动执行，一般无需手动）：

```
demo6_template.html 里的汉字
        │  提取 + 并入（单调只增）
        ▼
fonts/charset_live.txt        ← 全站字符集清单（当前 779 字）
        │  fontTools.subset --text-file=charset_live.txt --flavor=woff2 --no-hinting
        ▼
fonts/SHS-Regular.woff2 / SHS-SemiBold.woff2   ← 两字重子集（各约 150 KB）
        │  base64
        ▼
fonts/v5_font_reg.b64.txt / v5_font_sb.b64.txt ← 注入模板用
```

手动重切（等价于脚本内部命令，供排查）：

```bash
python3 -m fontTools.subset fonts/SourceHanSerifCN-Regular.otf \
  --text-file=fonts/charset_live.txt --flavor=woff2 --no-hinting \
  --output-file=fonts/SHS-Regular.woff2
# SemiBold 同理
```

**验收字体是否真的生效**：headless Chrome 的 `--dump-dom` 在 base64 字体场景下会挂死不 flush，所以字体核验必须走**真实 Chrome**，在控制台执行 `document.fonts.check('600 16px "Source Han Serif CN"', '某字')` 逐字确认为 `true`。

## 6. 内容模型：怎么改文案 / 加内容

所有内容都在 `demo6_template.html` 的 `/* ---------- data ---------- */` 区块，是一组 JS 常量。双语通过统一的字典结构表达。

### 6.1 三个核心工具函数

```js
let LANG = "zh";                              // 当前语言
const t = () => UI[LANG];                     // 取当前语言的 UI 文案字典
const pick = o => typeof o === "string" ? o : (o[LANG] || o.zh || o.en);  // 从 {zh,en} 里挑当前语言
const missing = o => typeof o !== "string" && !o[LANG];                   // 判断当前语言是否缺译
```

约定：凡是双语文本，要么写成字符串（两语通用），要么写成 `{zh:"…", en:"…"}`。渲染时用 `pick()` 取。切换语言时改 `LANG` 再调 `renderAll()` 全量重绘。

### 6.2 UI 字典

`UI = { zh:{...}, en:{...} }` 放全站固定文案：导航 `nav`、页头 `hd`、各 section 的 kicker/标题、按钮文字、搜索占位符、弹窗字段名、页脚等。改一句话通常就是改这里对应 key 的 zh 和 en。

### 6.3 数据数组

- **DIRS**（研究方向）：每项 `{zh:{t,d,k[]}, en:{t,d,k[]}}`，`t` 标题、`d` 描述、`k` 关键词标签。
- **SUP**（导师）：单个对象，含 `bio` / `tags`（关联 DIRS 下标）/ `hon`（荣誉）/ `contact` / `out`（代表成果，zh/en 各一个字符串数组）。
- **MEM**（成员）：`{ phd:[], ms:[{y:入学年, list:[{zh,en,mj:{zh,en}}]}], alumni:[…] }`。`mj` 是专业。目前 phd 为空，会显示"暂无"文案。要给某人加论文题目/去向等，可加 `top:{zh,en}` 字段，弹窗会自动显示。
- **PUBS**（成果）：`{ papers:[], projects:[], forums:[], books:[] }`。每条含 `zh/en`（标题）、`au`（作者/角色）、`vzh/ven`（出处）、`y`（年份，用于时间轴分组与筛选 chip）。
- **NEWS**（新闻）：数组，每项 `{tag, d:"YYYY-MM-DD", url?, zh:{t,s,b}, en:{t,s,b}}`。`tag` 对应分类（见模板 TAGS，索引 6 = 媒体报道）；`url` 可选，有则渲染"原文链接"胶囊；`t` 标题、`s` 摘要、`b` 展开正文（可空）。

### 6.4 加一条论文 / 一位成员 / 一条新闻

以加论文为例：在 `PUBS.papers` 数组里插入一条同结构对象，`y` 填年份。**改完务必重新构建**——因为新标题很可能带来 charset_live 里没有的汉字，构建脚本会自动把字补进字体子集（前提是 OTF 在位，见第 4 节）。

新闻的 `url` 只用**永久链接**。公众号推文的搜狗跳转链是带签名、几小时就失效的临时 URL，不能写进网站；永久链需在微信内打开推文「⋯ → 复制链接」获取。

## 7. 视觉与交互架构

- **榕树是结构主角**：从首屏树冠到贯穿各章的气根，是全站视觉主线。签名动效是 spine（主干）生长 + 树冠呼吸变形。
- **首屏地球**：Canvas 2D 画的镂空球。陆地用 `_land_b64.txt` 里的 120×60 bitmask，不填海，靠大气光晕 + GPAL + 屏幕空间主光塑形。倾斜 `tilt≈0.20`，初始经度让正面朝约 100°E；仅在非"减少动态"偏好下缓慢自转（每帧 `rot += 0.0016`）。为省算力，掩膜只在纵向偏移变化 >0.5px 或 resize 时才重读。
- **首屏布局**：左文字（`.hero-txt`，max-width 640）+ 右榕树浮岛（`#treeWrap` 绝对定位，`right:1.5vw`，宽 `min(46vw,69vh)`，用 top/bottom + margin 居中，**不要用 transform** 居中以免和视差冲突）。≤900px 堆叠居中。
- **视差系数**：地球 0.30 / treeWrap 0.14 / 前景枝 0.16（这些是调过的手感值，改动会明显影响观感）。
- **搜索浮层**：全屏覆盖，索引成员/论文/项目/论坛/专著/新闻。
- **成员弹窗**：点卡片弹出个人详情。
- **关注卡按钮**：在新闻时间线末端。用 `IN_WX = /MicroMessenger/i.test(navigator.userAgent)` 判断环境——微信内置浏览器点击跳公众号主页；微信外改为"复制公众号名称"并提示去搜一搜（因为 `profile_ext?action=home&__biz=…` 只在微信客户端内可解析，外部浏览器会被拦到验证墙）。

## 8. 踩过的坑（前端 / 构建类）

这些都是实际调试中反复踩到、已固化的经验，接手时能省很多时间：

- **改了模板文案，某些字基线错位** → 十有八九是引入了字体子集里没有的新汉字，回退成了系统字体。修：放入 OTF 重新构建，脚本会自动补字。构建末尾的字形守卫就是为拦这个而加的。
- **headless Chrome `--dump-dom` 挂死不输出** → base64 内联字体场景下的已知问题。字体/视觉验收一律走真实 Chrome，别信 headless 的 DOM dump 和截图。
- **`--window-size` 太小截图异常** → headless 窗口宽度有约 500px 下限，低于此值排版不可信。
- **连续 rAF 把 `--dump-dom` 饿死** → 首屏地球持续 requestAnimationFrame 会让自动化 dump 拿不到稳定帧。模板里用 `window.__freeze` 让动画 settle 后再截。
- **合成器丢掉 `opacity<1` 或带 `filter` 的 canvas** → 某些环境下 canvas 会变空白。对策：把透明度烘进 `globalAlpha`，freeze 后用 noop rAF 保活。
- **预览窗口首屏 canvas 空白** → 被遮挡的 webview 会暂停 rAF。对策：启动时同步 `paintOnce()`，再加看门狗 `setInterval`（rAF 静默 >500ms 就补绘），并监听 `visibilitychange`/`resize` 补绘。
- **后台标签页 rAF 和 CSS transition 暂停** → 验收排版时要么激活标签，要么注入 `.rv{opacity:1!important}` 强制显示。
- **CSS 优先级坑**：`html[lang] .kicker` 的特异性会压过 `.hero-txt .kicker`，需要给首屏 eyebrow 写更高特异性（如 `html[lang].hero-txt .kicker`）。
- **剪贴板复制失败**：`navigator.clipboard.writeText` 需要用户手势（user activation），脚本里合成的 `el.click()` 会被拒（NotAllowedError）。所以关注卡按钮的复制绑在真实点击事件上，并有 `execCommand('copy')` 兜底。
- **滚动状态验收**：滚动中的视觉靠 `audit/audit.js` 做计算式走查（读 `window.__audit`），比截图可靠。
- **手机端整页被压缩到左半边、右侧一大块深色** → 这是**横向溢出**：文档 `scrollWidth` 大于视口宽时，手机浏览器会整体缩小去"容纳"超宽内容，于是正文被挤到左侧、右边露出溢出区。历史上的两个溢出源：`.pub .venue` 的 `white-space:nowrap;flex-shrink:0`（长出处文字把行撑到 ~700px），以及首屏装饰层（雾带 `width:140%`、地球 canvas）从 `overflow:visible` 的 `#home` 里漏出去。修法：小屏下让 venue 可折行（`white-space:normal;flex-shrink:1;word-break:break-word`），并给 `#home` 加 `overflow-x:clip` 把装饰层裁在首屏内（用 `clip` 而非 `hidden`，避免把 `overflow-y` 逼成 `auto` 产生内层滚动条）。**验收硬指标：360/390/414/768px 下 `document.documentElement.scrollWidth === clientWidth`。** 复现方法：桌面 Chrome 里用一个 390px 宽的同源 `<iframe>` 嵌住页面测量（浏览器扩展的 resize 给不出真手机视口，headless 又有 500px 下限）。
- **手机端顶栏与抽屉导航**：≤900px 顶栏只保留 logo＋中心名（缩小、最多两行）＋中英切换＋汉堡按钮 `#menuBtn`；桌面 `#nav` 与搜索按钮隐藏，导航收进下拉抽屉 `#mDrawer`（内含搜索入口，点击后关抽屉并打开搜索浮层）。抽屉随 `header.scrolled:not(.on-paper)` 切换纸色/墨色两套配色，与下滑后的深色顶栏一致。**坑：章节 id 数组 `["home","about","members","pubs","news"]` 在 `renderStatic()` 里写了三处（`#nav`、`#mNav`、`#ftLinks`），增删或调序章节必须三处同步改**；滚动高亮选择器是 `nav a[data-sec]`，同时覆盖桌面导航与抽屉。成员区 ≤760px 改两列等宽网格：`.yrow` 变单列、年级标签作小标题加横线、`.mchip` 固定为"姓名＋方向"两行等高卡片，杜绝一行两行参差。

## 9. 部署与更新

线上是 GitHub Pages，从仓库根目录读 `index.html`。详见 `deploy/README.md`。两条路径：

- **常规**：本地 `git push`（若你的环境 git 正常）。
- **API 直传**：`deploy/deploy_index.sh` 走 GitHub Contents API 只更新 `index.html`；`deploy/publish_all.py` 走 Git Data API 一次性提交整个工作树。当本地 `git push` 的 https remote helper 不可用时（某些受管环境会拦截），API 直传是稳妥兜底。

Pages 触发后约 30 秒完成重建。验证：等 `gh api repos/OWNER/REPO/pages -q .status` 返回 `built`，再从外网打开 URL 确认标题与交互正常。

**仓库根目录必须保留空的 `.nojekyll` 文件（本仓库已带）。** GitHub Pages 默认用 Jekyll 处理整个仓库，而本仓库含中文命名的 `.md`、二进制 `woff2/jpg/webp` 与脚本，会让 Jekyll 构建卡住；构建挂起期间线上根路径直接返回 **404**。`.nojekyll` 让 Pages 跳过 Jekyll、原样输出静态文件。`deploy/publish_all.py` 做的是精确快照同步，只要本地保留 `.nojekyll`，它就会被一并同步、不会被误删——**千万不要删掉它**，删了线上会再次 404。

> 仓库当前是**公开**的（免费 GitHub Pages 要求公开仓库）。这意味着预览内容在正式上线前就可被公网检索。若不希望被搜到，可改为私有仓库 + 直接分发单文件，或迁到带访问控制的托管。

## 11. 二次开发注意事项

- **只改 `demo6_template.html`，永远不要直接改 `index.html`**（产物会被下次构建覆盖）。
- 改完**必须重新构建**，尤其涉及文案时——构建会顺带把新汉字补进字体子集。
- **批量改动用锚点补丁法**：不要手工逐处 find-replace 大模板（易漏易错）。写一个补丁脚本，列出 `(旧串, 新串, 标签)` 清单一次性应用，再构建 + `node --check` 防语法错。`tools/patch_v6_batch.py` 是这种脚本的历史样例。
- 新增素材：把源图放 `assets/`，用 `tools/prep_demo_assets.py` 之类脚本转 base64，在模板加对应 `{{XXX_B64}}` 占位符，并在 `reinject6.py` 里加一行 `.replace()`。
- 历史版本 v1–v5 冻结在 `legacy/`，不要在生产分支上改它们。

演进方向（内容管理、正式上线、备案、备份）见 `docs/CMS与演进路线.md`。
