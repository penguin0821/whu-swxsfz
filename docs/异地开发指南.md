# 异地开发指南：在另一台电脑上用 git 开发与推送

结论先行：**日常开发请在一台 git 正常的电脑上 clone 本仓库、改模板、构建、`git push`**。仓库里另外两个 `deploy/` 脚本只是"git 被拦时的兜底"，不是首选路径。本文给出从零到第一次推送的完整步骤、验收硬指标和常见报错速查。

---

## 1. 前提

| 需要什么 | 用途 | 何时才需要 |
|---|---|---|
| git | clone / commit / push |  always |
| GitHub 账号权限 | 推送到 `penguin0821/whu-swxsfz` | always |
| Python 3 | 跑构建脚本 `reinject6.py` | always |
| `fonttools` + `brotli`（`pip install fonttools brotli`） | 字体子集化 | **仅当引入新汉字** |
| 思源宋体 OTF（见 `fonts/README.md` 下载链接） | 子集化源 | **仅当引入新汉字** |

不装 fonttools / 不放 OTF 也能构建：脚本检测到 OTF 缺失会复用仓库里已提交的 woff2 子集，只打 WARNING。只有当你新增的文案里出现子集没有的汉字时，才需要下载 OTF 重新子集化。

GitHub 认证二选一：`gh auth login`，或配置 SSH 键后把 remote 换成 `git@github.com:penguin0821/whu-swxsfz.git`。

---

## 2. 第一次上手

```bash
git clone https://github.com/penguin0821/whu-swxsfz.git
cd whu-swxsfz
```

clone 下来的就是完整可运行工程：`demo6_template.html`（唯一真源）、`reinject6.py`（构建）、`assets/`、`fonts/`、`docs/`、`deploy/`、`legacy/`、`audit/`，根目录 `index.html` 是构建产物（也就是线上文件）。

---

## 3. 日常修改循环

```bash
# 1) 只改模板，永远不要直接改 index.html（产物会被构建覆盖）
$EDITOR demo6_template.html

# 2) 重新构建：注入素材、必要时自动补字体子集、跑字形守卫
python3 reinject6.py

# 3) 本地自查（见 §4 验收）

# 4) 提交并推送
git add -A
git commit -m "content: 更新某某内容"
git push origin main
```

push 成功后 GitHub Pages 约 30 秒重建，线上地址 `https://penguin0821.github.io/whu-swxsfz/`。

加内容（论文 / 成员 / 新闻）改的是模板里的 `PUBS` / `MEM` / `NEWS` 数组，字段含义见 `开发使用手册.md §6`。大批量改动用"锚点补丁法"（写补丁脚本一次性应用），不要手工逐处 find-replace。

---

## 4. 推送前验收（硬指标）

- `python3 reinject6.py` 构建成功，字形守卫无缺字断言。
- 产物 ≤ 1.6 MB；抽出最大 `<script>` 跑 `node --check` 通过。
- 真 Chrome 打开：语言门、中英切换、成员 / 成果 / 新闻各区渲染正常。
- **手机端无横向溢出**：360 / 390 / 414 / 768px 视口下 `document.documentElement.scrollWidth === clientWidth`。这条是硬指标——一旦有横向溢出，手机浏览器会把整页缩小，正文被挤到左半边（详见 `开发使用手册.md §8` 移动端坑）。
- 推送后等 `gh api repos/penguin0821/whu-swxsfz/pages -q .status` 返回 `built`，再从外网打开确认标题与交互。

---

## 5. 两条不要踩的红线

- **不要删根目录的 `.nojekyll`。** 没有它 Pages 会用 Jekyll 处理整个仓库（中文命名 md + 二进制 + 脚本会让构建卡住），构建挂起期间线上根路径直接 404。
- **不要直接改 `index.html`。** 它是产物，下次 `reinject6.py` 会覆盖；改内容一律改 `demo6_template.html`。

---

## 6. 如果这台电脑 git push 也被拦（受管环境）

某些受管终端会中断 `git-remote-https`（push 报 `remote helper 'https' aborted`）。这时用仓库自带的 API 兜底脚本，效果等同 push：

```bash
# 只更新线上 index.html（走 Contents API）
./deploy/deploy_index.sh index.html

# 或整棵工作树一次性同步（走 Git Data API：blobs → tree → commit → ref）
python3 deploy/publish_all.py penguin0821/whu-swxsfz --branch main --root . --message "site: 某次更新"
```

`publish_all.py` 做的是**精确快照同步**：本地有什么远端就有什么，本地没有的远端会被删。所以本地务必保留 `.nojekyll`，否则一次同步就把它删掉、线上再次 404。

---

## 7. 可选：重建一段干净历史

现有历史里有一个 51 文件的批量提交（当初绕开被拦的 git push、走 API 上传留下的），内容完全正确，只是粒度粗。若你希望从一个干净的单一初始提交开始：

```bash
cp -R <本地工程目录> whu-fresh && cd whu-fresh
git init && git add -A && git commit -m "init: 课题组网站 v6 完整工程"
git remote add origin https://github.com/penguin0821/whu-swxsfz.git
git push -f origin main     # 注意：force push 会覆盖远端历史
```

除非有明确理由，否则不必这么做——直接 clone 现有仓库更稳妥，历史粗不影响任何功能。

---

## 8. 常见报错速查

| 现象 | 原因 / 处理 |
|---|---|
| push 报 `remote helper 'https' aborted` | 本机 git https 被拦，改用 §6 的 API 脚本 |
| 线上根路径 404 | `.nojekyll` 丢了或 Pages 构建挂起；补回 `.nojekyll` 并等 `built` |
| 构建报缺字断言 | 引入了子集没有的新汉字；放好 OTF 重跑构建，脚本会自动补字 |
| 构建只打 WARNING 不补字 | OTF 缺失，脚本复用已提交 woff2；要补字先下载 OTF |
| 手机端正文挤在左半边 | 横向溢出，按 §4 硬指标排查 `scrollWidth` |
| Pages 状态一直 `building` / 中间一次 `errored` | 连续快速提交的竞态；以最新 HEAD 对应构建的 `built` 为准 |
